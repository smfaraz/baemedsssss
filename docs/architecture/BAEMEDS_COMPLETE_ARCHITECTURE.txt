1. EXECUTIVE SUMMARY & BUSINESS MISSION
================================================================================
BaeMeds US is a specialized, production-grade American healthcare e-commerce and
durable medical equipment (DME) distribution platform. 

The platform is purpose-built to deliver clinical-grade medical supplies—such as
Oxygen Concentrators, BiPAP/CPAP respiratory systems, suction apparatuses, patient
monitoring units, hospital beds, and mobility equipment—directly to patients,
caregivers, and healthcare institutions across the entire United States.

Unlike conventional consumer e-commerce, BaeMeds US operates at the intersection of
three strict regulatory and architectural environments:
1. Federal Healthcare & FDA Device Regulations: Enforces physician prescription
   requirements, clinical verification, and device classification rules.
2. HIPAA Technical Safeguards: Implements least-privilege role separation, data
   minimization, automatic PHI sanitization, and immutable audit logging.
3. US Commercial Standards: Strict USD currency locking, 50-state destination tax
   nexus routing, carrier-grade parcel/freight logistics, and tokenized PCI Level 1
   hosted payment checkout.

2. HIGH-LEVEL SYSTEM TOPOLOGY (THE BIG PICTURE)
================================================================================
The architecture is structured around a decoupled, hybrid-headless topology:

+-----------------------------------------------------------------------------+
|                                CLIENT BROWSER                               |
| (React 19 SPA + Vite + Tailwind CSS v4 + TypeScript + Modern Google Fonts)  |
+-----------------------------------------------------------------------------+
             |                                              |
             | HTTPS (GraphQL Storefront API)               | HTTPS / Fetch
             v                                              v
+-----------------------------+               +-------------------------------+
|      SHOPIFY COMMERCE       |               |     VERCEL EDGE FUNCTIONS     |
|       (Shopify Cloud)       |               |          (/api/*)             |
| - Product Catalog & Images  |               | - CSRF & Origin Validation    |
| - Inventory & Variant SKUs  |               | - Shopify Auth Session Cookie |
| - Authoritative USD Pricing |               | - Cart Customer Association   |
| - Hosted Checkout (PCI DSS) |               | - Address Sanitization        |
| - Order Lifecycle Webhooks  |               +-------------------------------+
+-----------------------------+                               |
                                                              | HTTPS / PostgREST
                                                              v
                                              +-------------------------------+
                                              |       SUPABASE CLOUD          |
                                              |      (PostgreSQL 15+)         |
                                              | - Row Level Security (RLS)    |
                                              | - 6-Role Granular RBAC        |
                                              | - Patient Prescriptions Table |
                                              | - Immutable Audit Logs Table  |
                                              | - Private Medical File Storage|
                                              | - Contact Inquiries Database  |
                                              +-------------------------------+

Three major tenets govern this topology:
1. Separation of Financial Authority: The client browser never calculates prices,
   discounts, or taxes for order placement. Shopify is the authoritative source of
   monetary calculations and checkout fulfillment.
2. Zero Local Cardholder Data: Card payments are never captured by BaeMeds edge
   servers or database tables; all transactions route through Shopify Hosted Checkout.
3. Segregation of Clinical Data: Clinical prescription documents, doctor details,
   and audit records reside within Supabase under strict cryptographic Row Level
   Security (RLS), isolated from third-party marketing and analytics scripts.

6. STATE MANAGEMENT & REACT CONTEXT LIFECYCLE
================================================================================
The application maintains two synchronized, decoupled global state providers:

A. AuthContext (`context/AuthContext.tsx`):
   - Maintains: `customer` (profile, default address, saved addresses, orders),
     `isAuthenticated`, `isLoading`, and authentication action methods.
   - Token Architecture: Leverages an HttpOnly, SameSite=Lax cookie
     (`__Host-baemeds_session`) managed entirely through edge functions (`/api/auth`).
     The raw Shopify customer token is NEVER exposed to client JavaScript or stored
     in browser localStorage, preventing token theft via XSS.
   - Lifecycle: On initial page load, `useEffect` triggers a lightweight GET request
     to `/api/auth`. If a valid session cookie exists, the edge function resolves the
     Shopify customer and populates state; otherwise, state gracefully defaults to guest.

B. CartContext (`context/CartContext.tsx`):
   - Maintains: `cart` (array of CartItem), `cartTotal`, `cartCount`, `checkoutUrl`,
     `cartId`, and mutation methods (`addToCart`, `updateQuantity`, `removeFromCart`).
   - Persistence: The active Shopify `cartId` is persisted in client localStorage.
     When the page reloads, the cart context fetches the authoritative lines and
     pricing directly from Shopify's GraphQL API.
   - Guest-to-Customer Seamless Transition: When an authenticated user initiates
     checkout, `syncCartWithCustomer()` executes a POST to `/api/cart`. The edge
     function runs `cartBuyerIdentityUpdate` to bind the customer's identity, saved
     addresses, and email to the checkout before opening the Shopify checkout page.

7. SHOPIFY COMMERCE ENGINE & INTEGRATION LAYER
================================================================================
Shopify serves as the core commerce and inventory ledger:

A. Storefront API Configuration:
   - Protocol: GraphQL via POST to `https://${SHOPIFY_DOMAIN}/api/2024-07/graphql.json`.
   - Access Token: Public Storefront API token scoped strictly to read-only catalog
     queries and checkout creation.
   - Private Admin Credentials: Zero Shopify Admin API keys exist client-side.

B. US Regional Context Injection:
   - When creating a cart (`createShopifyCart` in `lib/shopify.ts`), the mutation
     explicitly supplies:
     ```graphql
     mutation cartCreate($input: CartInput!) {
       cartCreate(input: {
         buyerIdentity: { countryCode: US }
       }) { ... }
     }
     ```
   - This guarantees that Shopify initializes line items, inventory rules, currency
     formatting, and domestic tax rules under United States context.

C. Product Catalog Normalization (`normalizeProduct`):
   - Extracts variants, gallery images, availability, and prices in USD.
   - Sanitizes legacy Indian currency symbols (converting `\u20b9` and mojibake to `$`).
   - Inspects authoritative Shopify Metafields:
     - `custom.requires_prescription`: Direct Rx requirement flag.
     - `custom.hcpcs_code`: Billing code for insurance reimbursement.
     - `custom.fda_classification`: Class I, Class II, or Class III designation.
   - Assigns `isRegulatoryVerified: boolean` (true if confirmed by metafield, false
     if an advisory estimate).

8. SERVERLESS API & BACKEND EDGE ROUTING LAYER
================================================================================
Edge functions running on Vercel provide a secure proxy between the browser, Shopify,
and Supabase:

A. `/api/auth.ts`:
   - POST `action: 'login'`: Calls `customerAccessTokenCreate` on Shopify. If valid,
     generates an encrypted, HttpOnly, Secure, SameSite=Lax cookie:
     `__Host-baemeds_session=<token>; Max-Age=2592000; Path=/; HttpOnly; Secure; SameSite=Lax`
   - POST `action: 'register'`: Calls `customerCreate`, validates password length (>=6),
     sanitizes names, and immediately logs the user in.
   - POST `action: 'recover'`: Triggers a password recovery email via Shopify.
   - POST `action: 'logout'`: Calls `customerAccessTokenDelete` and returns a Set-Cookie
     header expiring `__Host-baemeds_session`.
   - GET: Reads the incoming cookie header, queries the current customer profile, and
     returns sanitized customer data.

B. `/api/account.ts`:
   - POST: Adds a new delivery address for the authenticated customer.
     - Validates US 50 States + DC (`isValidUSState`).
     - Validates US 5-digit ZIP format (`isValidUSZip`).
     - Validates US 10-digit phone number and normalizes to E.164 (`toE164Phone`).
     - Sanitizes street, city, and names stripping HTML tags, event handlers, and nulls.
     - Calls Shopify's `customerAddressCreate` mutation.
   - DELETE: Removes an address via Shopify's `customerAddressDelete` mutation.

C. `/api/cart.ts`:
   - POST: Accepts `{ cartId }`. Extracts the customer session token from cookie,
     validates `cartId.startsWith('gid://shopify/Cart/')`, and executes
     `cartBuyerIdentityUpdate` on Shopify. Returns the refreshed `checkoutUrl`.

9. SUPABASE DATABASE ARCHITECTURE & ROW-LEVEL SECURITY (RLS)
================================================================================
All non-commerce healthcare data is stored in Supabase PostgreSQL under strict RLS:

A. Database Schema & Tables:
   1. `public.profiles`:
      - Columns: `id` (uuid, references auth.users), `first_name`, `last_name`, `phone`.
      - Security: Users can SELECT and UPDATE only where `id = auth.uid()`.
   2. `public.addresses`:
      - Columns: `id`, `customer_id` (uuid), `address1`, `address2`, `city`, `province`, `zip`, `country`, `phone`.
      - Security: Users can access and mutate only where `customer_id = auth.uid()`.
   3. `public.user_roles`:
      - Columns: `user_id` (uuid, primary key), `role` (text enum), `created_at`, `updated_at`.
      - Security: Users can view their own role; mutations restricted to `is_admin()`.
   4. `public.prescriptions`:
      - Columns: `id` (uuid), `user_id` (uuid), `order_id` (text), `file_path` (text),
        `file_name` (text), `mime_type` (text), `file_size_bytes` (integer), `status` (text enum),
        `clinical_reviewer_id` (uuid), `review_notes` (text), `created_at` (timestamptz).
      - Security:
        - SELECT: Customer views own records; Clinical Specialists and Admins view all.
        - INSERT: Customer uploads for self with status strictly `UNDER_REVIEW`.
        - UPDATE: Restricted exclusively to `clinical_specialist` and `super_admin`.
        - DELETE: Denied for all users (medical records retention).
   5. `public.audit_logs`:
      - Columns: `id` (uuid), `timestamp` (timestamptz), `actor_id` (text), `actor_role` (text),
        `action` (text), `resource` (text), `result` (text), `metadata` (jsonb), `ip_hash` (text).
      - Security:
        - INSERT: Append-only. Authenticated users can insert ONLY where `actor_id = auth.uid()`.
          Unauthenticated actors can insert ONLY as `actor_id = 'anonymous'`.
        - SELECT: Restricted exclusively to `compliance_officer` and `super_admin`.
        - UPDATE & DELETE: Strictly revoked and denied across all roles (Immutable).
   6. `public.enquiries`:
      - Columns: `id`, `type`, `product`, `name`, `phone`, `email`, `rental_duration`, `message`, `status`.
      - Security: Public INSERT allowed; SELECT and UPDATE restricted to `is_admin()`.
   7. `public.newsletter_subscribers`:
      - Columns: `id`, `email`, `subscribed_at`.
      - Security: Public INSERT allowed; SELECT restricted to `is_admin()`.

10. ROLE-BASED ACCESS CONTROL (RBAC) & PERMISSIONS MATRIX
================================================================================
The platform implements 6 distinct roles enforced at the database and API level:

+-------------------------+----------------------------------------------------+
| ROLE                    | AUTHORIZED CAPABILITIES & BOUNDARIES               |
+-------------------------+----------------------------------------------------+
| customer                | - View and edit own profile and addresses          |
|                         | - View own order history                           |
|                         | - Upload prescriptions for own orders              |
|                         | - CANNOT view other patients, staff roles, or logs |
+-------------------------+----------------------------------------------------+
| support_agent           | - Assist customers with orders and inquiries       |
|                         | - CANNOT view or review clinical prescriptions     |
|                         | - CANNOT access audit logs or escalate roles       |
+-------------------------+----------------------------------------------------+
| fulfillment_specialist  | - View shipping addresses, line items, and weights |
|                         | - Generate courier tracking numbers                |
|                         | - CANNOT view clinical diagnostic notes or Rx files|
+-------------------------+----------------------------------------------------+
| clinical_specialist     | - Review, approve, or reject uploaded prescriptions|
|                         | - Attach physician verification notes to orders    |
|                         | - CANNOT modify financial totals or system roles   |
+-------------------------+----------------------------------------------------+
| compliance_officer      | - Inspect immutable audit logs for HIPAA compliance|
|                         | - Review data access patterns and breach alerts    |
|                         | - CANNOT modify patient health records             |
+-------------------------+----------------------------------------------------+
| super_admin             | - Manage staff roles, catalog sync, and infrastructure|
|                         | - All mutations are permanently logged in audit log|
+-------------------------+----------------------------------------------------+

SQL Security Definer Functions:
- `public.get_my_role()`: Returns current user's role from `user_roles`.
- `public.has_role(required_role)`: Verifies role membership with search_path protection.
- `public.is_admin()`: Confirms super_admin status.

11. HIPAA TECHNICAL SAFEGUARDS & PHI SANITIZATION ENGINE
================================================================================
The platform establishes technical safeguards conforming to HIPAA Security Rule standards
(45 CFR Part 160 and Part 164, Subparts A and C):

A. Data Minimization & PHI Scrubbing (`server/auditLogger.ts`):
   Whenever an audit event is logged, `AuditLogger.sanitizeMetadata()` executes:
   1. Canonical Key Inspection: Converts metadata keys to lowercase and strips all
      underscores, hyphens, and whitespace (`key.toLowerCase().replace(/[_\s-]/g, '')`).
   2. Blocked Key Dictionary: Blocks 38+ direct and indirect HIPAA identifiers:
      - Personal Identifiers: `patientname`, `fullname`, `firstname`, `lastname`,
        `email`, `emailaddress`, `phone`, `phonenumber`, `mobile`, `dob`, `dateofbirth`,
        `ssn`, `socialsecuritynumber`.
      - Clinical Data: `diagnosis`, `condition`, `medicalcondition`, `clinicalnotes`,
        `prescription`, `prescriptiontext`, `rx`, `rxnumber`, `treatment`.
      - Provider & Insurance: `physician`, `doctor`, `npi`, `insurance`, `policynumber`,
        `groupnumber`, `memberid`.
      - Geographic Data: `address`, `address1`, `address2`, `street`, `zip`, `postalcode`.
   3. String Regex Value Sanitization: Even if a key is generic (e.g. `notes`, `message`),
      the string content is scanned with regex patterns:
      - SSN Regex: `\b\d{3}-\d{2}-\d{4}\b` -> `[REDACTED_SSN]`
      - Email Regex: `\b[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Z|a-z]{2,}\b` -> `[REDACTED_EMAIL]`
      - Phone Regex: `\b(?:\+?1[-. ]?)?\(?[2-9]\d{2}\)?[-. ]?\d{3}[-. ]?\d{4}\b` -> `[REDACTED_PHONE]`
   4. Recursive Array Preservation: Preserves array structures while deeply sanitizing
      each element, avoiding object corruption.

B. Access Control & Transmission Security:
   - Unique User IDs: Generated via cryptographically secure UUIDv4.
   - Encryption in Transit: Strict TLS 1.3 enforced across all connections.
   - Zero PHI in URLs: Query parameters never carry patient names, conditions, or SSNs.
   - Zero PHI in Analytics: Google Analytics scripts receive only anonymous page paths.

15. PRESCRIPTION (RX) WORKFLOW & CLINICAL GOVERNANCE
================================================================================
For regulated durable medical equipment (CPAP, BiPAP, Oxygen Concentrators), the
platform enforces an end-to-end clinical workflow:

A. Prescription Product Identification:
   - Products are designated with `requiresPrescription: true`.

B. Cart Gating & Legal Certification (`pages/CartPage.tsx`):

     `hasPrescriptionItem = cart.some(item => item.requiresPrescription)`.

   - The "Continue to checkout" button is strictly DISABLED until the customer checks

     "I certify that I have or will provide a valid medical prescription from a licensed

     - Supported MIME Types: `application/pdf`, `image/jpeg`, `image/png`, `image/webp`.
     - File Size Limit: Maximum 10 MB.
     - Optional link to an active Order Number.
   - Documents enter the clinical queue under status: `UNDER_REVIEW`.
   - Each upload triggers an audit log event (`PRESCRIPTION_UPLOAD`).

D. Clinical Review Lifecycle:
   - Allowed Statuses: `UPLOADED` -> `UNDER_REVIEW` -> `APPROVED` / `REJECTED` / `EXPIRED`.
   - Database RLS ensures only users with the `clinical_specialist` or `super_admin`
     role can transition a prescription to `APPROVED` or `REJECTED`.
   - Orders cannot be fulfilled or marked shipped until clinical approval is logged.

16. PAYMENT SECURITY & PCI-DSS ZERO-TOUCH ARCHITECTURE
================================================================================
The platform adheres to a zero-trust payment model:

A. Zero Cardholder Data Handling:
   - No customer credit card numbers, CVVs, expiration dates, or bank details are
     ever collected, transmitted, logged, or stored by BaeMeds frontend or edge servers.
   - Eliminates PCI-DSS SAQ-D scope, qualifying for the safest, lowest-risk PCI SAQ-A.

B. Authoritative Checkout Gateway:
   - When checkout begins, `/api/cart` associates the cart with the customer's identity.
   - The browser is redirected via `window.location.replace(cart.checkoutUrl)` to
     Shopify's PCI-DSS Level 1 certified hosted checkout.
   - Customers complete payment via Apple Pay, Google Pay, Shop Pay, or Credit Card.
   - Once payment settles, Shopify notifies the system via HMAC-SHA256 signed webhooks.
   - Client-side claims of payment completion are never trusted.

17. ADVERSARIAL SECURITY, DEFENSE-IN-DEPTH & ANTI-TAMPERING
================================================================================
The codebase has undergone red-team adversarial penetration testing and hardening:

A. Input Sanitization & Anti-XSS Engine:
   - Every text input in `/api/account.ts` and `lib/enquiries.ts` passes through `sanitizeInput`.
   - Strips `<>` HTML brackets, quotes, event handlers (`\bon\w+\s*=`), `javascript:`
     pseudoprotocols, and null bytes (`\x00`).

B. CSRF & Origin Validation:
   - All state-changing mutations (`POST`, `DELETE`) call `assertSameOrigin(request)`.
   - Verifies that `request.headers.get('origin')` matches `request.url` origin.

C. Production Security Response Headers (`vercel.json`):
   - Strict-Transport-Security: `max-age=63072000; includeSubDomains; preload`
   - X-Content-Type-Options: `nosniff`
   - X-Frame-Options: `DENY`
   - Referrer-Policy: `strict-origin-when-cross-origin`
   - Permissions-Policy: `camera=(), microphone=(), geolocation=()`
   - Content-Security-Policy: Whitelists only trusted domains (Shopify, Supabase, Vercel).

D. Mass Assignment & IDOR Defense:
   - Account update endpoints explicitly filter incoming keys using an allowed-set whitelist.
   - Role modifications (`role`, `isAdmin`) injected into customer requests are discarded.
   - Address and order queries are bound to cryptographic customer tokens; changing an
     ID in a URL or request body returns 401 Unauthorized or 403 Forbidden.
